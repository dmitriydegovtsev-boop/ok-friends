# OK-Friends — отчёт (этап 1: 19–20.10.2026, этап 2 — быстрый режим v0.2.0: 24.10.2026, этап 3 — v0.2.1: 27.10.2026)

Программа для друга: принимает входящие заявки в друзья в Одноклассниках и удаляет друзей.
С v0.2.0 — быстрый режим без «человечности» (по просьбе друга, риск блокировки он понимает).
Один файл `OK-Friends.exe` для Windows собирается на GitHub Actions.

Раздел 00 — что изменилось в v0.2.1 (всплывашки, потолок 6000, самовосстановление); раздел 0 — устройство
быстрого режима v0.2.0, кроме того, что заменено в 00. Разделы 1–6 ниже — этап 1 (v0.1.x): селекторы и
наблюдения там по-прежнему верны, а темп, разгон, рабочее окно, отвлечения и правила остановки из раздела 2

## 00. Что изменилось в v0.2.1 (27.10.2026)

### С чем пришёл друг (скриншоты и журнал 26.10)
- **А.** Удаление на всех аккаунтах вставало через 10–40 удалений: 10 раз подряд «меню «Прекратить дружбу» не
  появилось» → остановка. На скриншотах `*_stop.png`/`*_unconfirmed.png`: в левом верхнем углу страницы друзей —
  всплывашка ОК «<Имя> хочет с вами подружиться» с «Принять» и крестиком поверх верхних карточек; верхний ряд

  работает (за тот день у аккаунта 1388 удалений — клики рабочие).
- **Б.** После 6000 друзей приём не останавливался: ОК отвечал «максимальное количество друзей», программа
  считала это лимитом у человека и шла дальше — бесконечно.
- **В.** Приём иногда «зависал на странице» (на одном аккаунте — на 150), помогала перезагрузка.
- Окно «Неизвестный сертификат CA» на скриншоте — не от программы (не Chrome), не трогаем; в README — «Отмена».

### Что сделано
| | |
|---|---|
| Всплывашки | перед каждым действием `prep()`: видимые всплывашки — по разметке выше **и по признакам** (текст «…ружит…», «в друзья», «рекомендуем…», «заявк…», сидит в fixed-элементе, внутри крестик или «Принять») — закрываются крестиком (JS-клик по `.growl_close`/`×`/`[class*=close]`, никогда по элементу с текстом «Принять/Дружить/Добавить/Перейти…»), прячутся `display:none`, и на страницу вешается стиль `#okf-hide` со всеми селекторами выше + рекламная плашка. Стиль переживает перерисовку, так что новые всплывашки ОК, как правило, не становятся видимыми вовсе. Не трогаются списки, окно подтверждения и меню друга. Закрытые пишутся в журнал «закрыто всплывающее уведомление ОК: «…»» |
| Видимая зона | `aim()`: цель (аватар друга, кнопка «Принять») прокручивается в середину окна по вертикали (`scrollIntoView center`, если она не в средней половине окна); затем точка на цели, которую ничто не перекрывает (`elementFromPoint`, 9 точек от центра к краям) — так верхний ряд под шапкой наводится по нижней, видимой части аватара. Перекрыта — закрыть всплывашки, прокрутить на ∓160 px, проверить снова; поверх — ещё не спрятанное меню прошлого друга — увести мышь и проверить снова. Пункт «Прекратить дружбу» тоже проверяется `elementFromPoint` перед кликом. «Принять», не нажавшееся из-за выскочившей всплывашки, — закрыть всплывашки и нажать ещё раз |
| Рекомендации | карточки — только `[data-block='MyFriendsSquareCardsPagingB'] .user-grid-card[data-id]`, и дополнительно отбрасываются карточки с текстом «Добавить в друзья»/«Дружить» (`JS_FR_UIDS`); «Список пройден: осталось N» считает так же |
| Потолок 6000 | перед приёмом и после каждой перезагрузки страницы заявок (порции по ≈20, и обязательно раз в 100 принятий) — свой счётчик вкладки «Все», `parse_count` («5 873», «5\xa0873», «6K», «5,9K», «5,9 тыс.»). ≥ 5990 → «Друзей уже около 6000 — пригласи в группу и запусти удаление», приём не начинается. Окно ОК прямо про нас («у вас…», «вы достигли…») → тот же статус. Окна «максимальное количество друзей» (и прямо про человека, и неясные) — человек пропускается, но 3 подряд без единого принятия → тот же статус со скриншотом; исключение — все три прямо про человека, а свой счётчик ниже 5890: тогда это действительно три человека с полным списком, идём дальше |
| Самовосстановление | вместо «10 подряд — стоп»: после **3** неподтверждённых подряд — скриншот `*_recover.png`, закрыть окна ОК (крестик/«Закрыть» во всех видимых окнах, Escape), спрятать всплывашки и плашку, мышь в угол, перезагрузить страницу (друзей или заявок) с ожиданием `load`, продолжить; люди из этой серии получают ещё одну попытку (второй неуспех — пропуск до конца запуска). Любое успешное действие обнуляет счёт. После **3 перезагрузок подряд без единого успеха** — «Не получается продолжить — смотрите окно браузера» со скриншотом `*_stop.png`. Капча, «подозрительная активность», телефон, сертификат — по-прежнему стоп сразу |
| Профилактика | страница перезагружается каждые случайные 30–50 успешных действий, даже без ошибок (на ОК список перезагружается и после каждой порции видимых карточек — если порция больше) |
| Журнал | у каждого неподтверждённого — «поверх точки: тег#id.классы «первые слова»» (или «сама цель (…)» — значит, ничто не перекрывало, а ОК не ответил: как у друга во втором-третьем ряду) |
| Свёрнутое окно | `prep()` видит `document.visibilityState = hidden` и разворачивает окно через CDP `Browser.setWindowBounds {windowState: normal}`, в журнал «окно Chrome программы было свёрнуто — развернул». См. проверку ниже |
| Ошибка вместо пропуска | меню, спрятавшееся между «всплыло» и «взять координаты», раньше роняло весь запуск («Ошибка: bounding_box timeout») — теперь это неподтверждённое действие |
| Окно, README | заголовок v0.2.1; README: новые статусы, что программа сама закрывает уведомления и перезагружает страницу, окна других программ («Неизвестный сертификат CA») — «Отмена», окно Chrome программы не сворачивать |

### Как работает
| | |
|---|---|
| Приём | страница заявок → «Принять» по всем загруженным карточкам сверху вниз обычным `locator.click()`, пауза между нажатиями случайная 0,7–1,5 с → перезагрузка страницы заявок → снова, пока заявки не кончатся или не наберётся лимит. Если все загруженные карточки пройдены/пропущены — прокрутка вниз (догрузка) |
| Удаление | так же по карточкам друзей: мышь в центр аватара → пункт «Прекратить дружбу» по координатам → окно подтверждения с этим id → «Прекратить» → закрыть окно «удалён из списка»; после порции — перезагрузка списка. `do_not_delete.txt` работает как раньше |
| Проверка приёма | без перезагрузки: на карточке «Заявка принята», или кнопка исчезла (ждём ещё 1 с, не появится ли ошибка), или исчезла карточка. Ждём до 5 с |
| Проверка удаления | окно подтверждения закрылось (кнопки «Прекратить» больше нет); в журнал пишется, была ли надпись «удалён из списка ваших друзей» |
| Неподтверждённое | запись в журнал, человек пропускается до конца запуска, дальше следующий; остановка только после 10 неподтверждённых подряд («10 действий подряд не подтвердились — остановлено, смотрите окно браузера», скриншот). Скриншоты первых 5 неподтверждённых за запуск |
| «Максимум друзей» у человека | окно ОК или надпись на карточке с «максимальн…друз» (а также «нельзя добавить/принять», «не может добавить», «лимит друзей», «у пользователя … лимит»), пробелы нормализуются → закрыть (крестик/«Закрыть»/«ОК» внутри окна, затем Escape) → журнал «пропуск: у человека максимум друзей — имя (id)» → следующий. Не считается неподтверждённым. Реальную разметку этого окна воспроизвести не удалось (нужна заявка от человека с полным списком друзей) — распознавание по тексту видимых окон (`role=dialog`, `*modal*`, `*Modal*`, `*popLayer*`, `*notify*`), запасной путь — новая такая фраза в тексте страницы |
| Лимит у нас самих | «у вас максимальн…», «вы достигли», «вы не можете добавить», «ваш лимит» → «Похоже, достигнут потолок друзей ОК. Можно приглашать в группу» |
| Инциденты | капча, «подозрительн…», «подтвердите телефон/номер», «слишком много действий», «профиль заблокирован», «нарушение правил» → скриншот, статус «Нужна ваша помощь — смотрите окно браузера. | Отметки прошлых версий | при первом чтении `counters/*.json` без `"schema": 2` отметка инцидента снимается (в журнал «v0.2.0: отметка инцидента прошлой версии … снята»), всё остальное в файле остаётся как было, включая старые поля разгона |
| Незнакомая страница | нет списка и нет заглушки дважды → обычная остановка со скриншотом «Не нашёл список … — смотрите окно браузера» (без отметки инцидента) |
| Сертификат | `browser.goto` ловит `net::ERR_CERT_*`/`ERR_SSL_*` и страницу `chrome-error://` с «Подключение не защищено» → остановка, скриншот, статус «Chrome показал предупреждение о сертификате ok.ru — пришлите скриншот окна Chrome, программа не может это закрыть», в журнал код со страницы (например `NET::ERR_CERT_AUTHORITY_INVALID`). «Перейти на сайт» не нажимается, флагов вроде `--ignore-certificate-errors` нет |
| Окно | аккаунты; «Принять заявки», «Удалить друзей», «Стоп», «Сбросить и продолжить», «Открыть браузер / проверить вход» (оставлена: через неё делается первый вход в ОК); «Лимит за запуск» 1–6000, по умолчанию 6000 (`run_limit` в settings.json, больше 6000 урезается); счётчики сегодня/всего; статус; журнал; внизу «Запустить всё: принимать» (все сразу) и «Стоп всё». Старые поля settings.json (бегунки, разгон, часы) не удаляются, просто не читаются |

## 1. Что сделано

Python 3 + Playwright, настоящий Google Chrome (`channel="chrome"`), персистентный профиль на
аккаунт (`profiles/<имя>`), окно tkinter. Все файлы создаются рядом с .exe: `profiles/`, `logs/`,
`counters/`, `screenshots/`, `settings.json`, `do_not_delete.txt`.

| Модуль | Что делает |
|---|---|
| `ok_friends.py` | точка входа; в .exe без консоли перенаправляет stdout/stderr в `logs/app.txt` |
| `okf/gui.py` | окно: список аккаунтов, кнопки, бегунки 250–6000 шаг 50, предупреждение выше 500 (один раз на аккаунт), галочка «Разгон», рабочее время 7:00–1:00 (круглосуточно нельзя), счётчики, планка, статус, журнал, «Запустить всё» со сдвигом 1–10 мин, «Стоп всё»; окно «Установите Google Chrome» |
| `okf/worker.py` | поток на аккаунт: владеет Playwright и окном Chrome, команды «принять/удалить/проверить вход», «Стоп» не позже чем через одно действие, переоткрытие Chrome после закрытия окна руками |
| `okf/browser.py` | поиск Chrome по стандартным путям Windows/mac, запуск с профилем, флаг `--disable-blink-features=AutomationControlled` (navigator.webdriver = false нативно), проверка входа, добивание зависших процессов Chrome нашего профиля (psutil) |
| `okf/modes.py` | режимы приёма и удаления: селекторы ОК, темп, перерывы, отвлечения, инциденты, потолок, неподтверждённые действия |
| `okf/human.py` | мышь по кривой Безье с разной скоростью, промахи на 3–9 px с поправкой, прокрутка кусками 150–450 px с паузами; к карточке ниже экрана докручивает колесом, а не мгновенным scrollIntoView; «ёрзание» мыши в паузах |
| `okf/store.py` | `settings.json`, `counters/<аккаунт>.json`, `logs/<аккаунт>.txt`, разгон, рабочее окно, смена дня в полночь |
| `tools/` | скрипты разведки и проверок (не входят в .exe): `explore.py`, `test_ramp.py`, `send_requests.py`, `test_reopen.py`, `build.sh`, `make_icon.py` |

## 2. Лимиты, паузы и поведение (зашито)

| Параметр | Значение |
|---|---|
| Бегунки «Принятий/Удалений в день» | 250–6000, шаг 50, по умолчанию 250; выше 500 — предупреждение один раз на аккаунт |
| Разгон | старт 250; каждый спокойный день ×1,5 с округлением до десятков, не выше большего из бегунков; дневная планка режима = min(планка, бегунок режима); инцидент → /2 (не ниже 100), аккаунт стоит до конца дня, следующий день без роста; день без работы — без роста; галочка снята → планка = бегунок |
| Рабочее окно | по умолчанию 9:00–23:00, диапазон 7:00–1:00; вне окна не запускается и останавливается |
| Темп (v0.1.3) | сессиями: пауза между действиями 3–9 с, сессия 30–80 действий (число новое каждый раз), перерыв между сессиями 10–40 мин; так до дневной планки или до конца окна. Планка выполнена раньше → «Дневная планка выполнена, продолжу завтра». При планке > 1000: паузы 2–6 с, перерывы 2–8 мин. Если расчёт (`plan_pace`) показывает, что планка не укладывается в окно с запасом 10 %, паузы и перерывы ужимаются пропорционально, пауза не ниже 2 с, перерыв не ниже 1 мин; время самого действия (приём ≈ 3 с, удаление ≈ 9 с с перезагрузкой) ужать нельзя, и если не укладывается даже так — в журнале предупреждение, программа делает сколько успеет |
| Распределение пауз | 80 % в диапазоне, 15 % «задумался» (верх диапазона × 1,5–2,5), 5 % быстрые у нижней границы; во время пауз мышь иногда слегка ёрзает |
| Расчётная проверка | `tools/test_pace.py`, 200 разыгранных дней на планку: приём 250…6000 укладывается в 14/16/18 ч (6000 — с паузами 2–2,4 с); удаление до 3000 укладывается, 6000 удалений ≈ 22 ч — не укладывается ни в какое окно, план это сообщает |
| Отвлечения | через случайные 20–40 действий, интервал разыгрывается заново после каждого отвлечения: открыть профиль человека, прокрутить, задержаться 4–12 с; полистать 2–5 фото с вероятностью, которая сама случайна от 1/3 до 1/5 (новая на каждый раз); ≈ 1 из 12 отвлечений — лента или «Сообщения» на 25–40 с. Все величины случайные в диапазоне, ничего не повторяется ровно |
| Пропуски | ≈ 1 из 15 человек пропускается в этом проходе; в конце списка к пропущенным возвращаемся |
| Мелочи «под человека» (v0.1.3) | открыл список — 1–3 с осмотреться, иногда прокрутить и вернуться; перед «Принять» в 30 % случаев навести на фото или имя на 0,5–2 с; карточка ниже экрана докручивается колесом; мышь ёрзает в паузах |

## 6. Первый запуск у друга (по одному действию)

1. Проверить, что установлен Google Chrome; если нет — поставить с https://www.google.com/chrome.
2. Скачать https://github.com/dmitriydegovtsev-boop/ok-friends/releases/latest/download/OK-Friends.exe
3. Положить файл в отдельную папку, например `C:\OK-Friends\`.
4. Запустить OK-Friends.exe.
5. Если Windows показала «Система Windows защитила ваш компьютер» — нажать «Подробнее».
6. Нажать «Выполнить в любом случае».
7. Дождаться окна программы.
8. Нажать «Добавить», ввести имя аккаунта (например «Аккаунт 1»), нажать ОК.
9. Нажать «Открыть браузер / проверить вход».
10. В открывшемся Chrome войти в Одноклассники (логин, пароль, код из СМС).
11. Вернуться в программу, нажать «Открыть браузер / проверить вход» ещё раз.
12. Убедиться, что в статусе «Вход в ОК есть».
13. Оставить бегунок «Принятий в день» на 250 (на первый день).
14. Оставить галочку «Разгон» включённой.
15. Проверить рабочее время (9:00–23:00 по умолчанию).
16. Нажать «Принять заявки».
17. Следить за статусом и журналом; при «Нужна ваша помощь» посмотреть окно Chrome.
18. Прислать Павлу скриншот окна программы после первых 10–20 принятых.
