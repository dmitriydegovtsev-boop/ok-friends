# OK-Friends — отчёт по этапу 1 (19–20.10.2026)

Программа для друга: принимает входящие заявки в друзья в Одноклассниках и удаляет друзей
по одному, похоже на человека, с дневными лимитами и разгоном. Один файл `OK-Friends.exe`
для Windows собирается на GitHub Actions.

- Репозиторий (публичный): https://github.com/dmitriydegovtsev-boop/ok-friends
- Релиз: https://github.com/dmitriydegovtsev-boop/ok-friends/releases/latest
- Постоянная ссылка на .exe: https://github.com/dmitriydegovtsev-boop/ok-friends/releases/latest/download/OK-Friends.exe
- Инструкция для друга: `README.txt` (тот же текст в описании релиза)

## 1. Что сделано

Python 3 + Playwright, настоящий Google Chrome (`channel="chrome"`), персистентный профиль на
аккаунт (`profiles/<имя>`), окно tkinter. Все файлы создаются рядом с .exe: `profiles/`, `logs/`,
`counters/`, `screenshots/`, `settings.json`, `do_not_delete.txt`.

| Модуль | Что делает |
|---|---|
| `ok_friends.py` | точка входа; в .exe без консоли перенаправляет stdout/stderr в `logs/app.txt` |
| `okf/gui.py` | окно: список аккаунтов, кнопки, бегунки 250–6000 шаг 50, предупреждение выше 500 (один раз на аккаунт), галочка «Разгон», рабочее время 7:00–1:00 (круглосуточно нельзя), счётчики, планка, статус, журнал, «Запустить всё» со сдвигом 1–10 мин, «Стоп всё»; окно «Установите Google Chrome» |
| `okf/worker.py` | поток на аккаунт: владеет Playwright и окном Chrome, команды «принять/удалить/проверить вход», «Стоп» не позже чем через одно действие, переоткрытие Chrome после закрытия окна руками |
| `okf/browser.py` | поиск Chrome по стандартным путям Windows/mac, запуск с профилем, флаг `--disable-blink-features=AutomationControlled` (navigator.webdriver = false нативно), проверка входа, добивание зависших процессов Chrome нашего профиля (psutil) |
| `okf/modes.py` | режимы приёма и удаления: селекторы ОК, темп, перерывы, отвлечения, инциденты, потолок, неподтверждённые действия |
| `okf/human.py` | мышь по кривой Безье с разной скоростью, промахи на 3–9 px с поправкой, прокрутка кусками 150–450 px с паузами; к карточке ниже экрана докручивает колесом, а не мгновенным scrollIntoView; «ёрзание» мыши в паузах |
| `okf/store.py` | `settings.json`, `counters/<аккаунт>.json`, `logs/<аккаунт>.txt`, разгон, рабочее окно, смена дня в полночь |
| `tools/` | скрипты разведки и проверок (не входят в .exe): `explore.py`, `test_ramp.py`, `send_requests.py`, `test_reopen.py`, `build.sh`, `make_icon.py` |

### Селекторы ОК (разметка на 20.10.2026)

- Страница заявок: `/profile/<id>/friendRequests`; блок `#hook_Block_UserFriendRequestMRB`,
  карточка `.js-entity-item[data-entity-id]`, кнопка `button.js-entity-accept` (две копии под разные
  ширины экрана, нажимается видимая), успех — текст «Заявка принята», ошибка —
  `.entity-item_status.__error` («Ошибка принятия заявки»), счётчик вкладки `.nav_menu_tab-counter`.
- Список друзей: `/profile/<id>/friends`; контейнер `[data-block=MyFriendsSquareCardsPagingB]`
  (подгрузка прокруткой по 25), карточка `.user-grid-card[data-id]`; наведение на аватар
  `.user-grid-card_img` → меню `.sc-menu` с пунктом `a.u-menu_a[aria-label="Прекратить дружбу"]`
  (в ОК он называется так, а не «Удалить из друзей»; пункт нажимается по координатам, иначе меню
  прячется) → окно `#hook_Modal_popLayerModal` с полем `#field_userIds` = id человека и кнопкой
  `#hook_FormButton_button_delete_confirm` («Прекратить»). Проверка — после перезагрузки списка
  карточки с этим id нет (в текущей странице ОК оставляет карточку до перезагрузки).
- Профиль: прокрутка; миниатюры `#hook_Block_UserPagePortletPhotos a.photo[href*=PopLayerPhoto]`,
  просмотрщик листается стрелкой вправо, закрывается Escape.
- Рекламные плашки (`fixed_promo_banner`) перекрывают карточки внизу слева: один раз пробуем
  «Скрыть», затем проверяем пересечение аватара с плашкой и сдвигаем страницу.
- Тексты ОК содержат неразрывные пробелы («Пока нет\xa0друзей») — все сравнения нормализуют пробелы.

## 2. Лимиты, паузы и поведение (зашито)

| Параметр | Значение |
|---|---|
| Бегунки «Принятий/Удалений в день» | 250–6000, шаг 50, по умолчанию 250; выше 500 — предупреждение один раз на аккаунт |
| Разгон | старт 250; каждый спокойный день ×1,5 с округлением до десятков, не выше большего из бегунков; дневная планка режима = min(планка, бегунок режима); инцидент → /2 (не ниже 100), аккаунт стоит до конца дня, следующий день без роста; день без работы — без роста; галочка снята → планка = бегунок |
| Рабочее окно | по умолчанию 9:00–23:00, диапазон 7:00–1:00; вне окна не запускается и останавливается |
| Темп (v0.1.3) | сессиями: пауза между действиями 3–9 с, сессия 30–80 действий (число новое каждый раз), перерыв между сессиями 10–40 мин; так до дневной планки или до конца окна. Планка выполнена раньше → «Дневная планка выполнена, продолжу завтра». При планке > 1000: паузы 2–6 с, перерывы 2–8 мин. Если расчёт (`plan_pace`) показывает, что планка не укладывается в окно с запасом 10 %, паузы и перерывы ужимаются пропорционально, пауза не ниже 2 с, перерыв не ниже 1 мин; время самого действия (приём ≈ 3 с, удаление ≈ 9 с с перезагрузкой) ужать нельзя, и если не укладывается даже так — в журнале предупреждение, программа делает сколько успеет |
| Распределение пауз | 80 % в диапазоне, 15 % «задумался» (верх диапазона × 1,5–2,5), 5 % быстрые у нижней границы; во время пауз мышь иногда слегка ёрзает |
| Расчётная проверка | `tools/test_pace.py`, 200 разыгранных дней на планку: приём 250…6000 укладывается в 14/16/18 ч (6000 — с паузами 2–2,4 с); удаление до 3000 укладывается, 6000 удалений ≈ 22 ч — не укладывается ни в какое окно, план это сообщает |
| Отвлечения | через случайные 20–40 действий, интервал разыгрывается заново после каждого отвлечения: открыть профиль человека, прокрутить, задержаться 4–12 с; полистать 2–5 фото с вероятностью, которая сама случайна от 1/3 до 1/5 (новая на каждый раз); ≈ 1 из 12 отвлечений — лента или «Сообщения» на 25–40 с. Все величины случайные в диапазоне, ничего не повторяется ровно |
| Пропуски | ≈ 1 из 15 человек пропускается в этом проходе; в конце списка к пропущенным возвращаемся |
| Мелочи «под человека» (v0.1.3) | открыл список — 1–3 с осмотреться, иногда прокрутить и вернуться; перед «Принять» в 30 % случаев навести на фото или имя на 0,5–2 с; карточка ниже экрана докручивается колесом; мышь ёрзает в паузах |
| Порядок удаления | случайный: случайная глубина прокрутки, случайная карточка из загруженных |
| Остановки приёма | заявки кончились; дневная планка; ОК ответил ошибкой принятия трижды подряд или сообщил о лимите → «Похоже, достигнут потолок друзей ОК. Можно приглашать в группу» |
| Неподтверждённое действие | нажали, а привычного ответа ОК нет (нет «Заявка принята», человек остался в списке после перезагрузки) → немедленная остановка аккаунта, статус «Действие не подтвердилось — остановлено, смотрите окно браузера», скриншот. К следующему человеку программа не переходит. Исключение (согласовано): явная ошибка ОК при принятии считается несработавшим «Принять», трижды подряд → потолок |
| Инциденты | капча (`captcha` в адресе или элементах), тексты «введите код с картинки», «подтвердите номер/телефон», «профиль заблокирован», «слишком много действий», «подозрительн…», «нарушение правил», незнакомая страница (нет списка заявок/друзей и нет заглушки), элемент не нашёлся дважды подряд → скриншот в `screenshots/`, статус «Нужна ваша помощь — смотрите окно браузера», планка /2, аккаунт стоит до конца дня. Капча не обходится |
| Закрытое окно браузера | программа не падает, статус «Окно браузера закрыто. Нажмите кнопку ещё раз», остатки Chrome добиваются, следующая кнопка открывает Chrome заново |
| Нет сессии ОК | «Войдите в ОК в окне браузера и нажмите кнопку ещё раз», действий нет |
| Нет Chrome | окно «Установите Google Chrome» со ссылкой google.com/chrome |
| «Запустить всё» | все аккаунты, каждый в своём Chrome, старт со сдвигом 1–10 мин; «Стоп всё» снимает отложенные старты и останавливает работающих |
| Журналы | `logs/<аккаунт>.txt`: дата, режим, что сделано, планка, причина остановки; `counters/<аккаунт>.json`: сегодня/всего по режимам, планка и причина, дата первого запуска, день инцидента |

Служебные переменные для проверок (`OKF_AUTO`, `OKF_MAX_ACTIONS`, `OKF_SHOTS`, `OKF_PAUSE_SCALE`,
`OKF_DISTRACT_FIRST`, `OKF_FAIL_ACCEPT`, `OKF_FAKE_UNCONFIRMED`, `OKF_FAKE_NOW`) работают только
из исходников или в сборке с маркером `DEV_BUILD` (`tools/build.sh --dev`). В .exe для друга они
отключены, в окне их нет, паузы всегда полные.

## 4. Не проверено

На маке (нет данных или нужна Windows):
- «Стоп» и «Стоп всё» во время **приёма** (заявки кончились раньше; «Стоп» проверен в удалении,
  механизм общий — прерывание любой паузы не позже чем через 0,2 с).
- Имитация потолка (`OKF_FAIL_ACCEPT`: три несработавших «Принять» → «Похоже, достигнут потолок…»)
  и имитация неподтверждённого действия (`OKF_FAKE_UNCONFIRMED` → остановка) — написаны, не
  прогнаны: нужны карточки заявок. Проверить на первом запуске у друга из исходников или
  дождаться реального потолка.
- Кнопка «Отмена» в предупреждении бегунка (по коду возвращает на 500).
- Реальные тексты ОК при потолке друзей и при предупреждениях: ловятся по словам «лимит»,
  «максимальное число друзей», «не можете добавить», «слишком много действий» и т. п.; точные
  формулировки ОК неизвестны — при первом срабатывании сверить по скриншоту.
- Длинные прогоны (сотни действий, перерывы 20–40 мин) — только расчётно.

На Windows (ничего не запускалось):
- SmartScreen, запуск .exe без консоли, tkinter-окно, Playwright-драйвер из временной папки
  PyInstaller, поиск Chrome по `%ProgramFiles%`, `%ProgramFiles(x86)%`, `%LocalAppData%`.
- Добивание процессов Chrome через psutil на Windows.
- Закрытие окна Chrome руками на Windows (там закрытие окна завершает процесс, сценарий проще).

## 6. Первый запуск у друга (по одному действию)

1. Проверить, что установлен Google Chrome; если нет — поставить с https://www.google.com/chrome.
2. Скачать https://github.com/dmitriydegovtsev-boop/ok-friends/releases/latest/download/OK-Friends.exe
3. Положить файл в отдельную папку, например `C:\OK-Friends\`.
4. Запустить OK-Friends.exe.
5. Если Windows показала «Система Windows защитила ваш компьютер» — нажать «Подробнее».
6. Нажать «Выполнить в любом случае».
7. Дождаться окна программы.
8. Нажать «Добавить», ввести имя аккаунта (например «Аккаунт 1»), нажать ОК.
9. Нажать «Открыть браузер / проверить вход».
10. В открывшемся Chrome войти в Одноклассники (логин, пароль, код из СМС).
11. Вернуться в программу, нажать «Открыть браузер / проверить вход» ещё раз.
12. Убедиться, что в статусе «Вход в ОК есть».
13. Оставить бегунок «Принятий в день» на 250 (на первый день).
14. Оставить галочку «Разгон» включённой.
15. Проверить рабочее время (9:00–23:00 по умолчанию).
16. Нажать «Принять заявки».
17. Следить за статусом и журналом; при «Нужна ваша помощь» посмотреть окно Chrome.
18. Прислать Павлу скриншот окна программы после первых 10–20 принятых.
